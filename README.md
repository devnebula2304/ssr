# 翻墙协议现状：SSR、Shadowsocks、Trojan、Hysteria、AnyTLS

ssr、shadowsocks、trojan、hysteria 与 anytls 的现状，要分别看协议仓库、实现项目和客户端文档，不能由一个发布日期直接判断是否可用。这里用 ShadowsocksR 与 Trojan 协议的全称区分撞名含义，只记录公开页面状态，不给协议作效果评价。

## 仓库状态、发布标签与文档条目各有含义

仓库页面是否有归档标识，描述的是仓库呈现的状态。发布页出现某个标签，描述的是一条公开发布记录；客户端文档出现某个协议页，描述的是文档提供了相关配置资料。这几个观察可以并列，却不能互相替代。

例如，某仓库没有归档标识，并不自动给出最近发布时间；某文档列出协议字段，也不自动补出该协议首次被哪个内核版本支持。要回答“还能不能用”，还涉及具体实现和对应配置，本文没有用页面状态替这些项目下结论。

sing-box 的入站与出站列表本来就不是同一张表。mihomo 又有自己的出站目录，包含 ShadowsocksR、Shadowsocks、Trojan、AnyTLS 等条目。读取时先标明来自哪个方向与项目，不能把多个表拼成“全部客户端都具备”的清单。

本文的文档入口用 [sing-box 官方文档](https://sing-box.sagernet.org/) 和 [mihomo 官方文档站](https://wiki.metacubex.one/) 表示。它们用于核对字段及条目，不提供协议次序，也不把配置页的存在写成任意订阅格式都能导入。

## ShadowsocksR 的两个仓库要分别记日期

截至 2026-10-23，官方页面显示 shadowsocksrr 组织下的 Python 仓库未归档，最近推送日期为 2023-01-03，发布接口没有取得 release，以官方页面为准。该项目的介绍写它是 ShadowsocksR 的 Python 移植实现，许可为 Apache-2.0。对应入口是 [ShadowsocksR 仓库](https://github.com/shadowsocksrr/shadowsocksr)。

截至 2026-10-23，官方页面显示同一组织的 Windows 仓库未归档，公开版本记录为 4.9.2，发布日期为 2019-04-21，最近推送在 2022-09-09，以官方页面为准。它的 README 标题明确为 ShadowsocksR for Windows。不能把 Python 仓库的推送时间替换到这份实现上。

未归档与近年有没有新记录需要同时写，不能删掉日期后称持续开发。这里也不以发布时间较早推出已经停止或已经不能用。页面没有给出的维护承诺，保留为公开页面未写明。

mihomo 的文档包含 ShadowsocksR 专页，给出 `type` 为 `ssr`，并列有 `cipher`、`password`、`obfs`、`protocol` 等字段。该页没有确认 URI 订阅解析范围、实际二进制默认编译情况或最低内核版本，不能将文档条目扩写为这些结论。

截至 2026-10-23，官方页面显示 shadowsocks-rust 未归档，版本记录为 v1.25.0，发布于 2026-08-26，最近推送日期为 2026-10-23，以官方页面为准。项目介绍将其定位为 Shadowsocks 的 Rust 移植，许可是 MIT。阅读入口由 [shadowsocks-rust 官方仓库](https://github.com/shadowsocks/shadowsocks-rust) 指代。

原 shadowsocks-libev 地址在补取页面时重定向到 shadowsocks-c，目标页面可以打开，也没有显示归档标识。补取的发布源中出现 v3.3.6 与 v3.3.4。这里记录的是跳转和发布源读数，不把地址变化解释成代码、维护者或使用方式变化。

截至 2026-10-23，官方页面显示该 C 实现发布记录中的 v3.3.6 日期为 2020-09-15，以官方页面为准。页面没有取得可采用的许可证信息，因此本文不替它填写许可。也不拿 Rust 实现的许可或发布日期补全 C 实现。

mihomo 的 Shadowsocks 配置页使用 `ss` 类型，并列出加密算法分组。它与 ShadowsocksR 是两个文档条目，不能因为名称接近就交换字段或订阅说明。本文只讲公开状态，不从移植语言推断性能差异。

## Trojan 协议项目与返回错误的地址分开陈述

截至 2026-10-23，官方页面显示 Trojan 的 C++ 仓库可打开，页面没有归档标识，发布记录列出 Trojan 1.16.0，日期为 2020-03-25，以官方页面为准。页面显示 GPL-3.0 许可。这里的 Trojan 指代理协议项目，不采用其他同名软件含义。

同次读取中，trojan-gfw 组织下的 Trojan-Go 地址和发布源都返回 404。可以写的是当天的访问结果，原因则是公开页面未写明。这个结果不被改写为已停止开发、已迁移或整个 Trojan 协议已经不可用。

mihomo 的 Trojan 页列有 `password`、`network`、`ss-opts`、`reality-opts` 等字段。sing-box 的入站和出站目录也出现 trojan 条目。文档目录不能解释一个具体地址为什么返回错误，仓库访问结果也不能反过来删除其他项目文档里已经存在的条目。

Trojan 协议的最低内核支持版本，在本页取得的配置资料中没有明确写出。这里不提供补推版本，也不由某个项目日期推定全部实现的兼容范围。状态记录与配置参考保留为各自的资料。

## Hysteria 的代际与发布读数需要保留区别

Hysteria 的协议规范描述基于 QUIC 的 TCP、UDP 代理。官方另有代际对照，明确 Hysteria 2 与 1.x 的协议不兼容，连接两端需要同代实现。mihomo 也分别列出 hysteria 和 hysteria2 页面，不把两个名字当作可以随意互换的配置标签。

截至 2026-10-22，官方页面显示 Hysteria 的发布接口返回 app/v2.13.0，日期为 2026-10-05，以官方页面为准。补取记录则在 2026-10-23 的发布源中读到 extras/v2.13.0 对应 2026-10-05、app/v2.13.0 对应 2026-09-16。两个来源对标签日期的记录并列保留，不在本文合并成唯一发布时间。

仓库地址从 apernet/hysteria 重定向到 HyNetworks/hysteria，项目采用 MIT 许可。官方提供客户端与服务端的独立配置教程，也有协议与 URI 规范。资料入口使用 [Hysteria 官方仓库](https://github.com/HyNetworks/hysteria)，本文不复述效果宣传或身份隐藏相关描述。

sing-box 的更新日志在 1.5.0 写加入 Hysteria2；出站页还对部分后续字段单列版本。mihomo 的 Hysteria2 配置页则没有写首次支持的内核版本。某实现已注明版本，不允许把该版本挪给另一实现。

## TUIC 规范仓库与 AnyTLS 实现不是同一种对象

TUIC 仓库的 README 定义面向 TCP、UDP 中继的代理协议，并明确该仓库没有官方实现，专注协议设计。规范在 `SPEC.md`，协议版本字节为 `0x05`。阅读入口是 [TUIC 官方仓库](https://github.com/tuic-protocol/tuic)，不把协议仓库当作可执行客户端目录。

截至 2026-10-22，官方页面显示 TUIC 仓库未归档，默认分支最近提交为 2025-03-13，推送字段为 2025-05-15，以官方页面为准。这两个日期不同的原因，公开页面未写明。补取的发布源还列出 tuic-server-1.0.0 与 tuic-client-1.0.0，不能因此覆盖 README 对当前仓库不含官方实现的说明。

AnyTLS 的 Go 实现页面可打开，未显示归档标识。它与 TUIC 规范仓库不是同一类对象，不能把两者的提交或发布频率直接作比较。[AnyTLS 官方仓库](https://github.com/anytls/anytls-go) 用于识别该项目，不提供其他实现的状态。

截至 2026-10-23，官方页面显示 AnyTLS Go 实现的发布源列出 v0.0.13，日期为 2026-01-12，以官方页面为准。页面没有取得可用的许可信息，本页不补。mihomo 的 AnyTLS 配置页还明确排除了 AnyTLS 与 Reality 的组合，这个限制不因仓库存在发布记录而消失。

## 客户端文档里的版本只能对应明示范围

mihomo 的 AnyTLS 页记有从 v1.19.30 开始默认不再发送 client-metadata。这是行为变更版本，不是首次支持 AnyTLS 的版本；没有首次支持说明时，不能把两个问题合并。TUIC 页同样没有给出最低支持版本。

sing-box 的更新日志在 1.4.0 记录 TUIC 支持。它的 TUIC 出站页列出 `uuid`、`password` 等字段，却没有明确标成仅支持某一 TUIC 代际，因此本页不从字段相似推成“只支持 V5”。mihomo 自己区分 V4 的 `token` 与 V5 的 `uuid`、`password`，也只对应它自己的配置说明。

截至 2026-10-23，官方页面显示 sing-box 发布源同时列出 1.15.0-alpha.12 与 1.14.3，以官方页面为准。Xray-core 的公开发布名中出现 v26.10.21，但日期记录顺序存在差异，本文只保留发布名。两份发布资料分别以 [sing-box 官方发布页](https://github.com/SagerNet/sing-box/releases)、[Xray-core 官方发布页](https://github.com/XTLS/Xray-core/releases) 指代。

对照协议现状时，可以保留仓库、日期、文档字段与明确限制，不把缺项变成推断。协议名出现于目录，只确认有这一条资料；发布名存在，只确认有这一条发布。本文不据这些记录得出“应当选哪个”的结论。

TUIC 的规范描述依赖可多路复用、经 TLS 加密的流，主要设计用于 QUIC。命令类型包括 Authenticate、Connect、Packet、Dissociate、Heartbeat，每一项都有协议中的职责；这些是规范对象，不是某个图形客户端必须显示的菜单。规范的存在也不会确认任意程序实现了所有命令。

TUIC 页面还强调不同协议版本之间不保证兼容。现有主分支规范只描述版本字节 0x05，没有提供可用于确认另一代版本字节的资料，因此本文不自行写出映射。对 V4 和 V5 的认证字段区别，采用的是 mihomo 配置页的描述，不冒充旧代协议规范。

sing-box 的 TUIC 字段中有 `udp_relay_mode`，列出 native 与 quic，并将后者描述为经 QUIC 流提供的无损 UDP 中继，附带额外开销。另有 `udp_over_stream`，文档要求对端使用 sing-box 或兼容程序，并指出它与前述字段冲突。这是实现层面的限制，不能把一个实现的附加选项当成所有 TUIC 实现共同能力。

Hysteria2 的字段版本也存在类似区分。sing-box 出站页把 `server_ports`、`hop_interval` 标在 1.11.0 起，把 `hop_interval_max` 标在 1.14.0 起；这些版本各自限定字段，不会覆盖更新日志给出的协议加入版本。mihomo 对相应字段采用自己的命名，不能用替换标点的方式把两份配置互相翻译。

AnyTLS 文档页的空闲会话项目包括 `idle-session-check-interval`、`idle-session-timeout` 与 `min-idle-session`。这些字段说明文档给了什么配置入口，没有直接给出协议在所有场景的性质或效果。本文不以字段名字猜测默认参数，也不把版本发布记录用作默认值来源。

对于订阅，mihomo 的 provider 类型包括 http、file、inline，内容形式另有 yaml、uri、base64。两组分类属于不同问题，且内容形式不能在同一个文件混用；URI 示例出现的协议前缀，也不构成所有协议前缀都支持的完整列表。因此，即便配置目录里有协议专页，订阅解析范围仍不能由目录名称补全。

Hysteria 的官方客户端教程以 SOCKS5、HTTP 代理模式举例，完整配置页写从 2.4.1 起可以在同一端口同时提供这两种入口。这个客户端入口版本不等于协议代际，也不能据它推算 mihomo 或 sing-box 首次加入对应协议的时间。项目、接口和协议版本需要继续分栏。

认证字段也有明确的实现差异。官方 Hysteria2 的 userpass 把“用户名:密码”整体作为认证密码，sing-box 没有另提供这个别名，配合使用时对应到它的 `password` 字段。该说明只处理已有文档确认的字段关系，不给真实服务器、用户名或密码，也不把它转成全部实现互通的保证。

## FAQ

### SSR 仓库没归档，就能说仍在持续维护吗？

不能省略具体提交和推送日期。未归档只是一项状态，页面没有因此给出持续维护承诺。

### mihomo 文档有 SSR 页，就代表 SSR 订阅都能导入吗？

该页给出协议字段，没有确认 URI 订阅解析全貌。配置页存在与订阅导入范围需要分别核对。

### Trojan-Go 当天返回 404，能说协议已经停了吗？

只能陈述该地址及发布源的访问结果。原因未写明，不能外推整个协议或其他实现的状态。

### Hysteria 1 的配置能直接当成 Hysteria 2 吗？

官方明确两代协议不兼容。客户端与服务端需要同代，两个文档条目也分别存在。

### TUIC 仓库里就有官方客户端吗？

README 明确说当前仓库不含官方实现。协议规范与第三方实现列表，应按不同对象阅读。

### AnyTLS 的行为变更版本就是首次支持版本吗？

不是同一个问题，文档只确认该行为从特定版本改变。首次支持版本没有写明时，不能用变更版本替代。
