## 多平台支持要逐个平台验证

所谓“全平台”至少拆成 Windows、macOS、Android、iOS 和路由器。每行写推荐客户端、官方来源、最低系统版本、订阅格式、导入步骤和实际结果。支持系统不等于支持你指定的客户端。

iOS 应把客户端购买与节点服务分开；Windows 和 macOS 要记录 CPU 架构；Android 注意后台限制；路由器则看固件、内存和是否支持相应内核。只有 Logo 列表而无帮助文档，证据等级较低。

## 节点覆盖不按国旗数量计算

套餐页列出多少国家，不代表每个地区都有独立入口、低倍率或长期可用。测试时选择自己真正需要的两个或三个地区，记录节点名、连接成功次数、失败总数、时段和出口信息。

同一国家可能有多种入口和倍率；同名节点也会换线路。节点总数应和测试日期绑定，失效节点不能从分母删除。这样得到的结果才能解释稳定性，而不是只展示最好的一次。

1. **身份：**保存完整域名、公告入口、订单系统和付款主体，检查四者是否能互相指向；
